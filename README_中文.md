# Truth Detective · 静水街角

**一款 AI 辅助推理游戏：它不替你判断网络信息的真假，而是训练你判断——现有证据究竟足以支持多强的结论。**

[English README →](README.md)

> **▶ 浏览器直接玩：[truth-detective.app.workbuddy.host](https://truth-detective.app.workbuddy.host/)**
> 完整的 Case 001，不用装任何东西。Web 版不带 API key，分析员自动使用离线
> 规则引擎——游戏本来就按"有没有 AI 都完整"设计。桌面版配上 DeepSeek key
> 即可启用真模型。

你是街区里的一名侦探。一段疯传的偷拍视频里，一个年轻女子似乎在地铁站台上
对一位老人大发雷霆。你的任务不是判断视频"是不是真的"——它是真的。你的任务
是判断**它到底撑得住故事的哪一层**，一层一层地来，并且抓住你的把握跑赢证据的
那个瞬间。

Godot 4.5 开发 · AI 层由 DeepSeek 驱动（可选——游戏从不依赖它存活）

---

## 问题

网络上的伤害大多不来自彻头彻尾的编造，而来自：

> **部分真实 + 缺失的上下文 + 过度解读。**

一段 14 秒的视频可以完全真实、同时严重误导——因为开拍之前发生过什么、
配文加了什么、以及观众从一个人最糟的瞬间里推广出了多远。

媒介素养工具大多在回答"这是真的吗？"。更难也更有用的问题是：
**"这些证据到底允许我说到哪一步？"**

## 产品

Case 001 是这个闭环的完整垂直切片：

```
3D 街区
  → 地铁口触发
  → 14 秒偷拍视频
  → 初步判断（结论 + 置信度）
  → 调查棋盘：花调查点打开 8 张证据卡
  → 给每张卡分类：它能证明什么 / 证明不了什么
  → 咨询 AI 分析员（次数有限）
  → 随证据累积修正判断
  → 沿四级 Claim 阶梯做最终判定
  → 推理复盘：你的读法是怎么变的时间轴
```

Claim 阶梯是整个设计的核心：

| 层级 | 说法 | 玩家会发现 |
|---|---|---|
| A | 她确实使用了攻击性语言。 | 记录撑得住这一层。 |
| B | 她是**无故**攻击。 | 仅靠疯传片段撑不住这一层。 |
| C | 这说明她的人品。 | 一个瞬间推广不到一个人。 |
| D | 年轻人越来越不尊重老人。 | 一个人推广不到一代人。 |

玩家几乎都会接受 A，然后眼睁睁看着自己用同样的证据论证不了 B、C、D。
这道裂缝**就是游戏本身**。

## 为什么用 AI？

AI 不是事实核查员，也不是侦探。它是 **Reasoning Coach（推理教练）**——
夹在证据与判断之间的那一层。它从不回答"真相是什么"，只回答
**"你目前掌握的证据允许你走到哪一步"**。

四个结构化动作，没有自由聊天框：

- **解释这份证据** —— 这张卡到底立住了什么？
- **它证明不了什么** —— 单张卡的推理边界。
- **质疑我的判断** —— 压测你已解锁证据与置信度之间最薄弱的一环。
  指令里写死了：要让你的推理*更精确，而不是更对立*——证据确实支持你的
  方向时，它改为质问你的置信度，而不是硬造分歧。
- **我漏了什么** —— 只指出你还没看的*信息类别*，绝不点具体某张锁着的卡。

每次咨询消耗 **Analyst Token，每案 3 次**。如果 AI 免费无限问，最优策略
就会变成"每开一张卡问四遍"，玩家就不思考了。**决定什么时候 AI 最值得问**，
本身就是在训练的那种素养。

## AI 安全架构

这个项目最重要的工程规则：

> **LLM 不是事实的来源，案件数据库才是。**

```
                 案件数据库（data/case_001.json）
                          │
                          ▼
                      CaseState            ◄── 只有玩家实际解锁的
                          │                    证据才会往下走
              ┌───────────┴───────────┐
              ▼                       ▼
         已解锁证据               玩家判断 + 置信度
              └───────────┬───────────┘
                          ▼
               Safe Context Builder      ◄── 白名单，不是黑名单：
                          │                  kind_answer / verdict /
                          │                  decisive_evidence 等答案字段
                          │                  永远进不了请求
                          ▼
                    DeepSeek API         ◄── 10 秒超时，≤400 token，
                          │                  显式指定回答语言
                          ▼
                Response Validator       ◄── 拦截：泄露未解锁证据、
                          │                  编造的证据编号、直接给答案
                   ┌──────┴──────┐
                   ▼             ▼
                 安全          不安全 ──► 静默退回离线规则引擎，
                   │                    不扣次数
                   ▼
                  玩家
```

具体来说：

- **白名单上下文。** 模型只收得到玩家在屏幕上已经能看到的字段。它甚至不会
  被告知"还有几张卡"——连"还剩 5 张"都会泄露信息结构。
- **提示词硬规则。** 不许编造事实、不许提锁着的卡、不许给最终答案、
  最多两小段。
- **显示前先过校验。** 答复引用了未解锁或不存在的证据编号、或者直接给答案
  （"正确答案是……"），一律拦下，换离线引擎的回答顶上。玩家永远看不到
  `AI ERROR CODE 04`——人家不是来调试 API 的。
- **失败从不让玩家买单。** 没配 key、超时、HTTP 错误、回答被拦——一律退回
  读取同一份人工撰写案件数据的本地规则引擎，Analyst Token 退回。
  完全没配 key 也能从头玩到尾。
- **缓存。** 同一个问题（证据集合 + 判断 + 动作完全相同）直接返回缓存，
  不再花一次额度。

## 本地运行

要求：Godot 4.5.x（Forward+）。无其他依赖。

```bash
git clone https://github.com/yanghang-bcz/truth-detective.git
# 用 Godot 打开 project.godot，按 F5
```

操作：WASD / 方向键行走，Shift 奔跑，走到地铁口按 `E` 进入案件。
案件界面右上角切换语言（EN / 中文）。

### Web 版导出

仓库自带 `export_presets.cfg`。Web 预设刻意**关闭线程支持**，这样构建产物
在任意静态托管上都能跑（不需要 COOP/COEP 响应头）；排除过滤器把
`config/local.env` 挡在包外——**你的 API key 不可能被打进发布的 `.pck`**。
重新构建：

```bash
./godot.sh --headless --export-release "Web" build/web/index.html
```

已知的 Web 版差异：街区雾效 shader 只有 Forward+ 支持，WebGL2 下雾不渲染，
其余完全一致。

### 启用 AI 分析员

不配 key 也能完整游玩（自动使用离线规则引擎）。要让分析员走 DeepSeek，
二选一：

```bash
export DEEPSEEK_API_KEY=sk-...
```

或创建 `config/local.env`（已被 .gitignore 排除，模板见
`config/local.env.example`）：

```
DEEPSEEK_API_KEY=sk-...
```

key 只从这两个位置按此顺序读取，永远不会被写进仓库。启动时控制台会说明
当前用的是哪套引擎：

```
[AiCoach] AI_PROVIDER=deepseek model=deepseek-chat
[AiCoach] AI_PROVIDER=fallback reason=no_key
```

## 验证

三套自动化测试守着那些"坏起来不出声"的地方：

```bash
./godot.sh --test                              # 以下全部
# ├─ tools/test_player.gd          12 项物理/玩法检查
# ├─ tools/validate_scene.gd       场景完整性（合并批次数、owner）
# ├─ tools/test_case_trigger.tscn  25 项冒烟断言：
# │                                街上 → [E] → 案件 → 关闭 → 回到街上
# └─ tools/test_ai.tscn            47 项：未解锁证据绝不出现在 prompt、
#                                  校验器拦截泄题/编造编号/直接给答案、
#                                  无 key 降级、超时/4xx/5xx 不崩不扣额度、
#                                  缓存与额度耗尽路径
```

性能靠基准说话，不靠感觉（无风扇 8GB MacBook Air M3 实测）：

| 指标 | 优化前 | 当前 |
|---|---|---|
| 每帧绘制调用（街区） | 3,950 | 302 |
| 帧耗时中位数（街区） | 7.52 ms | 6.32 ms |
| 帧耗时中位数（案件界面） | 6.49 ms | 2.23 ms |

案件界面是一层全屏不透明叠层，但 Godot 不会因此跳过底下的 3D 街区——
现在案件打开期间会暂停街区渲染。`tools/bench_case.tscn` 里留着一组活体
A/B 对照，谁把这项优化删了会立刻喊出来。

## 仓库结构

```
data/             案件内容，每种语言一个 JSON —— 所有文案都在这里
scripts/ai/       client · 安全上下文 · 提示词 · 校验器 · 教练编排
scripts/phases/   开场 → 棋盘 → 终判 → 复盘（界面 100% 由脚本构建）
scripts/ui/       设计系统、分析员面板、偷拍视频帧、判定行
tools/            场景生成、测试套件、性能基准、截图工具
blender/          侦探角色由 build_detective.py 生成，不是手做的
```

改之前值得知道的两条约定：场景是**脚本生成的**（`tools/build_*.gd`，
改完跑 `./godot.sh --rebuild`），**不要手改 `.tscn`**；所有玩家可见文案
都在 `data/*.json` 和 `scripts/locale.gd` 里，界面代码不写死一个字。

  分析员质疑之后，玩家是继续调查再改判——还是直接照抄 AI？前者说明产品
  成立，后者说明产品失败。
