## 0. 结论摘要

V0.3 PRD 中标记为 P0 的全部条目已实现，并通过「单元测试 + 真实浏览器鼠标交互」双重验证。

**唯一未在浏览器内验证的链路**：地图走位（A/S/D/W）与地铁口 `[E]` 触发进案件。
原因是当前 headless Web 环境中键盘事件无法进入 Godot 画布（DOM 侧确认收到 `isTrusted=true` 的 keydown/keyup，引擎侧无响应），
属**运行环境限制，不是代码缺陷**。该链路由 `test_input_map`（11 项）、`test_metro_reachability`（1 项）、
`test_case_trigger`（25 项）覆盖，且案件内部全部流程改为以案件场景为启动场景后完成真实鼠标验收。

因此：**V0.3 的 P0 要求在「案件内部」范围内已全部完成并可宣称达成**；「从街头走进地铁口」这一段不宣称已在浏览器验证。

本轮**未** Push、**未**重新部署、**未**修改现有公开试玩版本。

## 2. P0-A：Confidence 真实鼠标拖动

**方法**：不使用代码设置滑条数值。通过 CDP 下发 `mousePressed → mouseMoved×N → mouseReleased`（`buttons=1`），
在 1600×1000 视口（dpr=1，与游戏逻辑视口 1:1）上真实按住手柄拖动。判定手柄位置用「竖条高度 ≥14px」识别，
避免中文标签亮像素污染；百分比按相对轨道 `(handle_x - track_x0)/(x1 - x0)` 换算，避免语言切换导致整体位移的误判。

| 阶段 | 起点 | 拖动后 | 结论 |
| --- | --- | --- | --- |
| Intro | 50% | **80%** | 读数同步、手柄发光、松手不回弹 |
| Investigation | 80%（继承） | **45%** | 继承自 Intro，拖动生效 |
| Final Review | 45%（带入） | **69%** | 带入当前值，未回落 50% |

三处拖动的共同结果：滑条数值、界面上显示的百分比、`CaseState` 中保存的值三者一致；离开页面再返回仍是拖动后的值。

对应单元测试：`[conf] 拖动后滑条值真的变了（= 85）` / `松手产生了一次 committed 结算` /
`重进页面回显保存过的把握（期望 85，实际 85）` / `回显值不是默认的 50（v0.2 的「切页回落 50%」不复现）`。

**修掉的根因**：`ConfidenceSlider._ready()` 原先无条件覆盖 `custom_minimum_size`，把滑条宽度打成 0；
现改为仅在 `custom_minimum_size.x <= 0` 时补默认值。

## 3. P0-B：Judgment State 完整继承链

在浏览器中按 PRD 指定的完整路径走了一遍，每步截图：

```
Intro（Suspicious / 80%）
  → 进入调查板，Claim B 显示 Suspicious / 80%（继承，非默认值）
  → 切到 Claim C：空白 / 50%（不串味）
  → 切回 Claim B：Suspicious / 80%（恢复）
  → 改判 Unsupported，把握拖到 45%
  → 进 Final Review：B 显示 Unsupported / 45%（带入）
  → 返回调查板：仍是 Unsupported / 45%
  → 再进 Final Review：四条全部保留
  → 提交终判
```

关键点：**初判（initial）没有被调查阶段的改判覆盖**。`initial_judgments` 只在 `confirm_initial()` 写入一次，
`select_judgment()` 只写 `current_judgments`；`final_judgments` 只在 `confirm_final()` 时对 current 做快照。
测试佐证：`[state] 操作 A 不影响 B`、`[state] 终判之后改 current 不会污染 final 快照`。

## 4. P0-C：三阶段中英切换不丢状态

四个阶段各切一次往返，逐项对照：

| 阶段 | 切换前 | 切回后 |
| --- | --- | --- |
| Intro | 未提交草稿 Suspicious / 80% | 草稿与把握都在，且**不会被代提交**成初判 |
| Investigation | Unsupported / 45%，已解锁 E01 | 判断、把握、已解锁、已花点数、事件条数均不变 |
| Final Review | 四条已填 | 四条与把握全部保留 |
| Debrief | 已生成的复盘 | 内容随语言重生成，评分与统计数字不变 |

**保证机制**：`reload_for_language()` 只重载 `data` 与 `points_total`，**不触碰任何判定容器**。
Intro 的草稿是独立单槽位 `intro_draft`，切语言时从它读数，而不是从 `initial_judgments` 猜。
测试佐证：`[lang]` 45 项，含 `切到 zh 后事件条数不变（期望 3，实际 3）`、`切到 en 后事件条数不变（期望 3，实际 3）`。

## 5. Judgment Event History

浏览器实测：一次完整流程后，判定历程只有 **2 条**，无覆盖、无重复计数。

```
1. FIRST READING        Suspicious   →  80%
2. REVISED              Unsupported  →  80%
```

第 2 条的把握是 **80** 而不是 45 —— 因为改判发生在拖到 45% 之前，随后的拖动单独记一条 `CONFIDENCE_ADJUSTED`。
这正是 PRD 要求的「事件记录修改前后数据」，且时间点正确。

对照 PRD 的计数规则（`[events]` 25 项全过）：

| 规则 | 测试项 | 结果 |
| --- | --- | --- |
| Initial Confirmed = 1 | `初判记 1 条事件` | 1 |
| Judgment Revised = 1 | `Judgment Revised = 1` | 1 |
| Claim A 首次作答不计入 Revision | `Claim A 首次作答不计入改判` | 0 |
| Final Confirmed 不计入 Revision | `Final Confirmed 不计入改判` | 1（未增） |
| Confidence Adjusted 按实际计 | `把握调整记 1 条` / `一次拖动只记 1 条` | 与实际一致 |
| 拖动过程中不记事件 | `拖动过程中**不**记事件` | 0 |
| 被打断的拖动也结算 | `被打断的拖动也会结算，不留「显示变了、事件没有」的缺口` | 1 |
| 重复结算不重复记账 | `重复 commit_pending 不重复记账` | 1 |
| 证据快照不被后续解锁改写 | `历史里的证据快照是深拷贝` | 通过 |

`_record_event()` 中 `"unlocked_evidence_ids": unlocked.duplicate()` 为深拷贝，这是「历史不被覆盖」的直接保证。

## 6. 四种玩家 Debrief

**方法**：不看评分函数返回值，而是真实构建 `DebriefPhase` 节点树、递归收集渲染出的文本，再从文本里取统计条数值。
浏览器侧另用截图复核（D24–D32）。

| 场景 | 期望 | 实测 |
| --- | --- | --- |
| A 全对 | 4/4，不编造错误 | 显示 4/4，逐条给「你的判定 vs 参考」+ 解释，**无纠错卡、无训练要点** |
| B 错两项 | 2/4，明确解释 | 显示 2 / 4；每条错误项给出该选项专属解释；换选项后旧解释消失；错误多于两张时出现展开按钮 |
| C 选 Insufficient | 按 `verdict_accepts` 判为一致 | D 选 Insufficient 判为一致；C 选 unsupported 不算一致，得 3 / 4；「缺口」与「矛盾」解释区分 |
| D 不用 AI 且多次改判 | 统计准确 | 改判 3 次显示 3、把握调整 2 次显示 2、咨询 0 次显示 0，并**如实说明没问过分析员**，不编造 AI 协作评价 |

**能力评级已彻底移除**：7 个场景的渲染文本统一断言「不含能力评级词」，命中均为「无」。
`README.md` 与 `README_中文.md` 中残留的「三项推理模式 STRONG」表述已同步改写为
「逐条给出一致数（n / 4）与逐条解释，不产出能力评级」。

另有一项 PRD 未明确要求但属于「不编造」范畴的行为：判断一致但关键证据从未解锁时，
复盘会如实提示「决定这条的材料从未被打开」，而不是默认玩家看过。

## 7. AI Analyst 兼容性

浏览器真实往返（`claim=B`，`target=E01`，当时已解锁 1 条证据）：

```
[AiCoach] -> deepseek action=explain claim=B target=E01 unlocked=1
<-- source=ai action=explain ok=true tokens_left=2 failure= blocked=
```

回答严格限定在已解锁的 E01 范围内，并明确指出「无法证明 without provocation」——
即**没有泄露未解锁证据**，也没有为了显得聪明而超出证据边界。

逐条对照：

| 要求 | 实现 | 验证 |
| --- | --- | --- |
| 读最新 Current Judgment | 组装上下文时取 `current_judgment/current_confidence` | 浏览器实测上下文含当前判断 |
| 请求发起时保存快照 | 快照存 judgment / confidence / 已解锁证据 | `[ai] 历史里记的是**提问那一刻**的判断` |
| 等待期改答案不污染 | 回复只用快照写历史 | `[ai] 把握同样是提问那一刻的快照（期望 80，实际 80）`；回复时刻状态另存一处供排查 |
| Evidence Whitelist | 只放行 `CaseState.unlocked` 内的证据 | `[ai] 记下提问时解锁了哪些证据（期望 2，实际 2）`；实测 `unlocked=1` |
| Response Validator | 校验结构，失败降级 | `test_ai` 47 项含 Validator 分支 |
| Fallback | 网络/额度失败时给出不冒充 AI 的兜底文案 | `test_ai` 优雅降级分组 |
| 未解锁证据不泄露 | 上下文里就不包含 | 浏览器实测回答未提 E02–E08 |

### `godot.sh --test` 不再吞掉失败

原写法每段都是 `run_script xxx.gd | grep -E "^(PASS|FAIL)" || true`：
管道退出码取的是 `grep` 的，`|| true` 又把它抹平一次，**这条命令从来没有能力失败**。

现改为 `seg()` 逐段执行、逐段记录 `$?`，任一段非零即 `exit 1` 并点名失败段。

**实证**：把 `tools/test_player.gd` 临时替换为 `quit(1)` 的失败探针后，
`./godot.sh --test` 返回 **1**，日志出现
`!! == 玩法回归测试 == —— 该段退出码 1` 与 `== 测试未通过：1 / 7 段失败 ==`。
之后还原文件，`git status` 干净。

另注：Godot 对**不存在的脚本**返回 0，所以「文件被删」这种情况这条测试发现不了；
失败探针是唯一能证明退出码可信的方法，本轮已做。
